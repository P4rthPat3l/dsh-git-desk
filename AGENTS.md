# dsh-git-desk

- TypeScript, ES modules. Host sources live in `src/host/` and compile to `dist/` with `tsc`; the browser client is bundled from `src/client/` by esbuild into `client.js`. The wire shapes both halves use are in `src/contract.ts`. Run `npm run typecheck` before `npm run build`; `npm test` loads the built bundle in jsdom and the compiled host entry in Node. The built output is committed because the profile links this folder and the harness imports it without a build step.
- The profile installs this directory as a symlink (`~/.dsh/profiles/web/node_modules/dsh-git-desk` → this checkout) through `dsh plugin --profile web add link:$PWD`, which also appends `dsh-git-desk` to `dsh.profile.bundles`. Because it is a link, a rebuild is enough: the host half loads after the DSH app restarts, the rebuilt `client.js` after a window reload. Remove it with `dsh plugin --profile web remove dsh-git-desk`.
- The Plugin Manager artwork is `icon.png`, a 512 × 512 PNG exported as `./icon` and included in the npm `files` list. DSH accepts PNG icons up to 256 KiB; keep artwork inside the package. This asset does not replace the panel's small theme-aware Git glyphs.
- There is no DESIGN.md. The design system is the Harness one. Use only `--dsw-*` and `--dsh-*` tokens. The token values and the primitive component CSS ship inside `/opt/DSH NEXT/resources/app.asar` (`dsh-client-ui-theme/lib/client.js`, `dsh-client-ui-primitives/lib/*.module.css`, `dsh-web-frontend/dist/assets/index-*.css`). Extract them with `npx @electron/asar extract-file` to check a value.
- Native conventions copied from those primitives: body 13px/20px, meta 12px/18px, secondary text `--dsw-alias-label-tertiary`, radius sm 8 / md 12 / xl 20, hairline outlines through `inset box-shadow` with `--dsh-hairline-width`, focus ring `--dsw-alias-state-business-primary`, primary button `--dsw-alias-button-primary-fill` (neutral, not blue).
- The plugin must not import `@deepseek-ai/dsh-client-ui-primitives`. It reproduces their styles in the `CSS` string inside `src/client/main.ts`.
- `client.js` installs that stylesheet once at module scope, guarded by `style[data-plugin-css="dsh-git-desk/styles"]`. It is not rendered inside the panel, because the session header button needs the styles while the tab is closed.
- The session header button lives in the `conversation.session.header.utilities` and `conversation.hero.options` list slots, keyed by `sessionId`. A tab body reports whether it is on screen into `visibilityOf(sessionId)`, because the slot knows nothing about the right sidebar and the button has to show its pressed state.
- The stylesheet hides the built-in change request header button with `button[data-forge-header]{display:none}`. That marker belongs to `@deepseek-ai/dsh-experimental-client-ui-forge`. If a host update renames it, the rule silently stops matching and the button comes back; the panel and its tab are never touched.
- A Cordis bundle patch can disable another bundle's row by id (`- id: forge-panel` plus `disabled: true`), and a nested row inside a `group: true` config is addressable because `applyPatches` maps groups recursively. Do not use this to remove a host feature: it also removes everything else that row provides, and it only lands when this bundle's patch layer applies after the host bundle's.
- Every visible string goes through `t()` with both `EN` and `ZH` entries in `client.js`.
- Panel preferences live in this browser under `localStorage` key `dsh-git.preferences.v1`, exposed as the module-scope `prefs` store with the native `{ getSnapshot, subscribe }` hook shape. `model: null` and `instruction: ''` mean "no override", so the host falls back to `agentDefaultModel` and its shipped wording.
- The Git settings page is a `settings.section` registration with id `git`, order 25, plus a matching `settings.section.icon`. A single preference that needs no page of its own belongs in `settings.general.item` instead.
- Keyboard commands register through `ctx.inject(['shortcuts'], ...)`, not through a hard `inject`, so a profile without the shortcuts package still loads the panel. All four commands ship with `defaults: {}` so the native Keyboard shortcuts dialog lists them unassigned; the user records the binding there and it is persisted by the harness, not by us.
- Commands run outside React, so the tab body writes the module-scope `panelBridge` on every render and `gitCommands` reads it. It is `null` whenever no tab body is mounted, and a command whose action is unavailable returns `{ status: 'blocked', reason }` instead of running.
- The list and diff columns of Changes and History are split by one draggable divider, `ColumnResizer`. The width is shared by both views and stored under `localStorage` key `dsh-git.split`; the list keeps 220px, the diff keeps 280px, and CSS `max-width` caps the column when the panel narrows. The hairline, the 8px grab area, and the hover line are copied from the dockkit divider.
- The commit message fields (`.gitp-commitbox textarea` and the branch dialog) auto-grow through `useAutoGrow`. They must keep no fixed `max-height` and no manual resize handle: a generated title plus body has to be readable as written. The field fits its content up to 45% of the panel height and refits when the column width changes.
- The commit instructions only replace the style paragraph of the system prompt in `src/host/lib/ai.ts`. The `FORMAT` rules stay appended: a title line in `type(scope): summary` form, then a blank line and a short body. `cleanMessage` keeps the body and normalizes only the title, because the log reads the first line and the panel shows the rest.
- History commit actions are a menu opened by right-click on a commit row or by the ellipsis in the detail header. They call four endpoints: `undoCommit`, `revertCommit`, `cherryPickCommit`, and `resetToCommit`. The host, not the client, enforces every guard, and the menu disables a row with the reason visible under its label.
- Undo is HEAD-only and `--soft`; it keeps the message and returns it to Changes. Revert requires a clean index because `git revert --no-commit` mixes with whatever is already staged, and it leaves a pending revert until the user commits, which the History menu treats as an operation in progress. Cherry-pick commits immediately and aborts on conflict. Reset requires `confirm: true` and one of soft, mixed, or hard.
- `status` now reports `reverting` and `cherryPicking` from `REVERT_HEAD` and `CHERRY_PICK_HEAD`, alongside `merging` and `rebasing`. A history action is refused while any of the four is present.
- The panel follows the Session's working directory, not the workspace repository. `src/client/main.ts` sends `sessionDir` from the `workingDirectory` Session projection (`projectionValues.workingDirectory`) and falls back to the row `cwd`, which is the original project and never changes. The host resolves that directory to a checkout and returns `sessionRoot` plus `worktree` (`sessionCheckout` in `src/host/lib/git.ts`). A linked worktree is a checkout whose `rev-parse --git-dir` differs from its `--git-common-dir`. `discoverRepositories` lists each repository first and its worktrees right after it, and the picker nests them on that order. A worktree the Session chose is never written to the stored repository pick, because it stops being right when the Session leaves it.
- Pull runs with `--ff-only --no-rebase`, so a repository that sets `pull.rebase` still cannot rewrite local commits. When Git refuses the update because local changes are in the way, `pull` stashes, retries, and pops with `--index` so staged files stay staged. Untracked files join the stash only for an "untracked working tree files would be overwritten" refusal, and in that case every untracked file is stashed. A pop that cannot apply cleanly keeps the stash and returns `autoStash: 'conflict'`; the client switches to Changes and shows a notice that the 8-second status poll does not clear. Before the pop, the host re-reads `refs/stash`; a different stash on top makes the pull leave its stash in place: a failed retry throws, a successful retry keeps the stash and returns `autoStash: 'conflict'`.
- Skip hooks is a checkbox in the commit box and the branch dialog. The host adds `--no-verify` to `git commit` only when the request sets `noVerify: true`, for a normal commit, an amend, and branch and commit. The state is not persisted and defaults off, so hooks run after a reload.
- Discard changes is the trash control in the diff header. `discardPaths` requires `confirm: true` and matches only the exact selected entry paths; the client sends `entry.path` only, and the host expands a rename by its recorded old path. It restores tracked paths with `git restore --source=HEAD --staged --worktree`, deletes untracked paths with `git clean -f`, and refuses a selected conflict, any merge, rebase, revert, or cherry-pick in progress, and a rename whose old path holds another unselected file. An untracked nested repository is not deleted; the host reports `git/discard-incomplete` when a requested untracked path survives. Pathspecs use `:(literal)` so a wildcard character in a file name cannot widen a delete.
